# 撰寫技能

建立或修改 skill 的流程。skill 不是文件——它是塑造行為的程式碼。每一個用詞都會影響 AI 的行為模式。

## Skill 的本質

Skill 是**行為指令**，不是知識文件。

| 知識文件 | Skill |
|---------|-------|
| 描述事實 | 規範流程 |
| 被動參考 | 主動引導行為 |
| 可以模糊 | 必須精確 |
| 讀了有收穫 | 讀了會改變做法 |

## Skill 格式

```markdown
---
name: 技能名稱
description: 一行描述——什麼時候觸發、做什麼。這行會出現在 skill 清單裡，是 AI 判斷要不要載入的依據。
---

# 標題

[skill 內容]
```

### 關鍵欄位

**name**：中文，簡潔，一看就知道是什麼
- 好：`思考整理`（slug: brainstorm）、`完成驗證`（slug: verify）、`系統排查`（slug: debug）
- 壞：`通用輔助工具`、`工作流程`

**description**：觸發條件和功能的一行摘要
- 要寫清楚「什麼時候用」和「做什麼」
- 這行是 AI 判斷是否載入 skill 的唯一依據——寫不好就不會被觸發
- 好：`遇到任何非預期狀況時，系統化地找出根本原因再修。嚴格型 skill。`
- 壞：`偵錯工具`

## 撰寫流程

### 1. 定義目的

回答這三個問題：
- 這個 skill 要解決什麼問題？
- 沒有這個 skill 時，AI 會怎麼做？（這是你要改變的行為）
- 有了這個 skill 後，AI 應該怎麼做？

### 2. 確定類型

**嚴格型**：必須照做，不可彈性調整
- 適合：驗證、排查、測試等紀律性流程
- 用語：「鐵律」「不可協商」「必須」

**彈性型**：原則固定，應用方式可調
- 適合：思考整理（`brainstorm`）、設計探索等創意性流程
- 用語：「建議」「依情境調整」「原則」

### 3. 撰寫內容

**結構**：
1. 核心原則（一句話）
2. 什麼時候用
3. 流程步驟
4. 各任務類型的應用（如果是通用 skill）
5. 自我欺騙警訊（rationalization prevention）
6. 紅旗清單
7. 和其他 skill 的關係

**寫作原則**：
- 用正面表述：「先做 X 再做 Y」比「不要跳過 X」有效
- 解釋原因：「因為...」讓 AI 能在邊界情況做判斷
- 具體舉例：抽象原則配上具體案例
- 避免模糊：「品質要好」不是指令，「pattern checklist 6 項全過」是指令

### 4. 防合理化

AI 會找理由跳過 skill。你需要預判常見的合理化藉口，然後在 skill 裡封堵。

**常見格式**：

```markdown
| 藉口 | 現實 |
|------|------|
| 「太簡單不需要」 | 簡單的更容易出錯。 |
| 「這次特殊」 | 每次都說特殊。 |
```

### 5. 測試

**手動測試**：在新 session 中測試 skill 是否如預期觸發和引導行為。

測試方法：
1. 開新 session
2. 說出應該觸發 skill 的話（例如「幫我修這個 bug」→ 應觸發系統排查 `debug`）
3. 確認 skill 被觸發
4. 確認 AI 遵循 skill 的流程
5. 刻意說出應該被 skill 擋住的話（例如「先改試試看」→ 系統排查 `debug` 應阻止）
6. 確認 skill 有效阻止

## 存放位置

新的 skill 放在 plugin 的 `skills/<技能名稱>/SKILL.md`。

如果 skill 有輔助文件（子代理指令模板、參考資料等），放在同一目錄下：
```
skills/技能名稱/
├── SKILL.md          ← 主文件
├── 子代理指引.md      ← 輔助文件
└── 參考資料.md        ← 輔助文件
```

## 修改現有 Skill

修改 skill 跟修改程式碼一樣嚴肅：
- 理解現有 skill 為什麼這樣寫
- 不要改動經過調校的措辭（防合理化表格、紅旗清單）除非有證據證明改了更好
- 測試修改後的行為變化

## Skill 品質檢查清單

- [ ] name 和 description 清楚且準確
- [ ] description 包含觸發條件
- [ ] 核心原則一句話能概括
- [ ] 流程步驟可操作（不是模糊的建議）
- [ ] 有防合理化的藉口表
- [ ] 有紅旗清單
- [ ] 標明類型（嚴格 / 彈性）
- [ ] 標明和其他 skill 的關係
- [ ] 在新 session 中測試過觸發和行為
