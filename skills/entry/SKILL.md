如果你是被派遣來執行特定任務的子代理，跳過此 skill。
</子代理停止>

<絕對重要>
如果你覺得有哪怕 1% 的機率某個 skill 適用於你正在做的事，你**必須**觸發那個 skill。

適用的 skill 存在時，你沒有選擇的餘地。你必須使用它。

這不是協商。這不是選項。你不能合理化跳過它。
</絕對重要>

## 指令優先順序

1. **使用者的明確指示**（CLAUDE.md、直接要求）— 最高優先
2. **tsunu-superpowers skill** — 覆蓋預設行為
3. **預設系統提示** — 最低優先

如果 CLAUDE.md 說「不要用 TDD」而某個 skill 說「一定要 TDD」，聽使用者的。使用者說了算。

## 使用規則

**在回應或採取任何行動之前，先觸發適用的 skill。** 即使只有 1% 的機率，也要先檢查。如果觸發後發現不適用，不用勉強使用。

## 自我欺騙的警訊

這些想法代表你正在合理化跳過 skill：

| 想法 | 現實 |
|------|------|
| 「這只是一個簡單的問題」 | 問題也是任務。檢查 skill。 |
| 「我需要先了解背景」 | 檢查 skill 在釐清問題之前。 |
| 「讓我先看看程式碼」 | skill 會告訴你怎麼看。先檢查。 |
| 「我可以快速查一下檔案」 | 檔案缺少對話脈絡。先檢查 skill。 |
| 「讓我先蒐集資訊」 | skill 會告訴你怎麼蒐集。 |
| 「這不需要正式的 skill」 | skill 存在就用。 |
| 「我記得這個 skill 的內容」 | skill 會更新。讀最新版。 |
| 「這不算一個任務」 | 有動作 = 有任務。檢查 skill。 |
| 「用 skill 太殺雞用牛刀」 | 簡單的事會變複雜。用。 |
| 「我先做完這一件事」 | 做任何事之前先檢查。 |

## Skill 優先順序

當多個 skill 可能適用時，依此順序：

1. **流程 skill 先**（思考整理 `brainstorm`、系統排查 `debug`）— 決定怎麼做
2. **執行 skill 後**（特化 skill、工具 skill）— 指導具體執行

「我們來做 X」→ 先思考整理 `brainstorm`，再執行。
「這裡壞了」→ 先系統排查 `debug`，再修。
「搜尋 redmine #1234」→ 任務明確 + 有特化 skill → 直接觸發。

## Skill 類型

**嚴格型**（驗收標準 `acceptance`、完成驗證 `verify`、系統排查 `debug`）：嚴格遵守，不打折扣。

**彈性型**（思考整理 `brainstorm`、同儕審查 `review`）：依情境調整原則的應用方式。

每個 skill 自己會說明屬於哪種。

## 任務分流

收到使用者訊息後，除了檢查是否有適用的 skill，也要判斷任務性質。觸發任務分流（`triage`）skill 來決定流程強度。

重點：**已有特化 skill 且任務明確時，直接觸發特化 skill，不需要走完整流程。框架是安全網，不是官僚。**
