# 交付收尾

任務做完後，確保：結果交付了、品質確認了、該通知的人知道了、工作環境收拾乾淨了。

## 流程

```
所有任務完成
    │
    ▼
1. 最終驗證（觸發完成驗證 `verify` skill）
    │
    ▼
2. 判斷任務類型 → 走對應的收尾流程
    │
    ▼
2.5 更新工作筆記（backlog、計畫）
    │
    ▼
3. 通知相關人員
    │
    ▼
4. 清理工作環境
```

## 各任務類型的收尾

### 程式開發

**第一步：驗證測試通過**

```bash
# 跑專案的測試
npm test / cargo test / pytest / go test ./...
```

測試失敗 → 不能繼續，先修。

**第二步：提供選項**

```
實作完成。你想怎麼處理？

1. 合併回主分支
2. 推上去開 Pull Request
3. 保留分支（我之後處理）
4. 捨棄這次的改動
```

**各選項的操作：**

| 選項 | 合併 | 推送 | 保留工作區 | 清分支 |
|------|------|------|-----------|--------|
| 1. 合併 | ✓ | — | — | ✓ |
| 2. PR | — | ✓ | ✓（需要 iterate） | — |
| 3. 保留 | — | — | ✓ | — |
| 4. 捨棄 | — | — | — | ✓（force） |

選項 4 需要使用者輸入「捨棄」確認。不能無確認就刪。

### 教學影片

**第一步：三層 review**
1. 自審：pattern checklist、技術品質
2. 同儕審查（`review`，如果有其他agent在線）
3. 使用者最終確認

**第二步：交付方式**
- 測試用 → gofile 交付（不上 YouTube）
- 正式版 → 上 YouTube（需使用者確認）

**第三步：更新紀錄**
- 更新 scores.md
- 如有 Discord 通知需求，發通知

### AI 算圖

**第一步：品質確認**
- 評圖標準（合理性、生命感、技術面、細節）
- 釋出前隱私檢查

**第二步：交付方式**
- 群組分享 → 直接發
- 對外平台釋出 → 確認 metadata 沒有隱私資訊
- 私下交付 → 指定方式送達

### 通用任務

**第一步：確認產出**
- 對照需求，確認都做到了
- 品質自檢

**第二步：交付**
- 告知使用者完成了
- 附上產出物的位置或連結
- 說明任何注意事項

### 由其他 session 委派的任務

**第一步：正常收尾流程**

**第二步：回報委派者**
- 使用原委派通道回報結果摘要
- 更新委派訊息指定的紀錄

**第三步：更新值班表**
- 只有委派契約指定共享狀態檔，而且檔案確實存在時才更新

## 更新工作筆記

工作筆記（backlog、計畫的 checkbox）只留現況，過期內容等於死程式碼：重讀的人會照著它把做完的事報成還沒做。

- **做完的項目在同一個 commit 裡刪掉**（或打勾），不要等之後再整理
- 做的過程中發現筆記寫錯或過時，直接改成正確的版本，不留「已更正」的說明
- 回報「剩下哪些工作」前，逐項對照 repo 現況與對話確認真的還沒做，不照筆記念

## 通知

完成後需要通知的對象：

| 對象 | 時機 | 方式 |
|------|------|------|
| 使用者 | 重要任務完成 | 當前對話直接說 |
| 委派者 | 跨 session 委派完成 | 原委派通道 |
| 其他 agent | 影響到他們的變更 | 已驗證且獲授權的協作通道 |

## 清理

- **git worktree**：合併或捨棄後清理（PR 和保留不清）
- **暫存檔案**：確認不需要後刪除
- **Monitor / Cron**：任務完成後停掉不再需要的監控
- **虛擬桌面**：GUI 操作完成後關閉隔離桌面

## 紅旗

- 沒驗證就宣稱交付
- 忘記通知委派者
- 沒確認就刪除工作成果
- force push 沒問使用者
- 影片沒過三層 review 就上 YouTube
- 工作做完了，backlog 還掛著那一項
