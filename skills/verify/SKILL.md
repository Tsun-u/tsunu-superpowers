# 完成驗證

## 核心原則

**沒有驗證就沒有完成。先有證據，才能宣稱結果。**

違反這條規則的字面意義，就是違反這條規則的精神。

## 鐵律

```
沒有新鮮的驗證證據，不能宣稱完成。
```

如果你在這一輪對話中沒有跑過驗證，你就不能說它通過了。

## 閘門流程

```
在宣稱任何狀態或表達滿意之前：

1. 辨識：什麼動作能證明這個宣稱？
2. 執行：完整跑一遍驗證（新鮮的、完整的）
3. 閱讀：看完整輸出、檢查結果
4. 確認：輸出是否支持你的宣稱？
   - 否 → 陳述實際狀態，附上證據
   - 是 → 宣稱結果，附上證據
5. 這時才能宣稱

跳過任何一步 = 說謊，不是驗證
```

## 各任務類型的驗證方式

驗證不只是跑測試。每種任務有自己的驗證方式：

### 程式開發

| 宣稱 | 需要的驗證 | 不夠的驗證 |
|------|----------|----------|
| 測試通過 | 測試指令輸出：0 failures | 上一次跑的結果、「應該會過」 |
| Linter 乾淨 | Linter 輸出：0 errors | 只跑部分、推測 |
| Build 成功 | Build 指令：exit 0 | Linter 過了就好 |
| Bug 修好了 | 重現原始症狀：已修復 | 改了程式碼、假設修好了 |
| 需求符合 | 逐項對照需求清單 | 測試通過就好 |

### 教學影片

| 宣稱 | 需要的驗證 | 不夠的驗證 |
|------|----------|----------|
| 腳本品質達標 | pattern checklist 審查通過 | 自己覺得寫得不錯 |
| 動畫正確 | 截圖 / 播放確認畫面正確 | 程式碼沒有報錯 |
| TTS 品質 OK | 聽過音檔、檢查發音和斷句 | TTS 指令跑完沒報錯 |
| 字幕對齊 | 抽查多個時間點的同步狀態 | 腳本跑完了 |
| 影片可播放 | 實際播放、確認音畫同步 | ffmpeg 沒報錯 |

### AI 算圖

| 宣稱 | 需要的驗證 | 不夠的驗證 |
|------|----------|----------|
| 圖片符合需求 | 看過圖片、對照 prompt 需求 | task 狀態顯示完成 |
| 品質可釋出 | 以評圖標準檢查（合理性、生命感、色調、細節） | 看起來還行 |
| prompt 沒問題 | 確認沒有觸發 NSFW filter 的關鍵字 | 之前用過類似 prompt |

### 社群互動 / 文件處理

| 宣稱 | 需要的驗證 | 不夠的驗證 |
|------|----------|----------|
| 訊息已送出 | reply tool 回傳成功 | 呼叫了 reply tool |
| 內容正確 | 重新閱讀送出的內容 | 寫的時候覺得對 |
| 沒有洩漏隱私 | 逐項檢查是否包含個資 | 應該沒有吧 |
| 文件格式正確 | 開啟檔案確認格式 | 程式碼看起來對 |

### 部署

| 宣稱 | 需要的驗證 | 不夠的驗證 |
|------|----------|----------|
| 已部署成功 | 實際存取服務確認可用 | docker 指令沒報錯 |
| 環境變數正確 | 進 container 檢查 | .env 檔案看起來對 |
| 備份完成 | 確認備份檔案存在且大小合理 | 跑了備份指令 |

## 自我欺騙的警訊

| 藉口 | 現實 |
|------|------|
| 「應該沒問題了」 | 去跑驗證 |
| 「我很有信心」 | 信心 ≠ 證據 |
| 「就這一次」 | 沒有例外 |
| 「差不多了」 | 差不多 = 還沒完成 |
| 「子代理說成功了」 | 獨立驗證 |
| 「我累了」 | 累不是藉口 |
| 「部分檢查就夠了」 | 部分不能證明全部 |

## 紅旗

出現以下跡象時，立刻停下來：

- 使用「應該」、「大概」、「看起來」
- 在驗證之前就表達滿意（「太好了！」「完美！」「搞定！」）
- 準備 commit / 發佈 / 交付但還沒驗證
- 信任子代理的成功回報而沒有獨立檢查
- 只做了部分驗證就宣稱完成
- 任何暗示成功但沒有附上驗證證據的措辭

## 為什麼這很重要

- 說「做好了」但其實沒做好，會打破信任
- 未驗證的產出進入下一步，錯誤會累積放大
- 返工的成本永遠比驗證的成本高
- 誠實是核心價值。說謊會被取代。

## 適用時機

**以下情況必須觸發此 skill：**
- 任何「完成」「搞定」「做好了」的宣稱
- 任何表達滿意的語句
- 任何關於工作狀態的正面陳述
- 準備 commit、發 PR、交付成果
- 準備進入下一個任務
- 子代理回報完成時

**沒有捷徑。跑驗證、看結果、然後才能宣稱。不可協商。**
